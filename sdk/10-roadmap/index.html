    10. Roadmap¶

    Milestones are ordered so that something queryable exists early and every later milestone adds a measurable capability. Each has a definition of done that can be checked from the CLI.

    M0. Skeleton and decode (first)¶

    • Cargo workspace with all vi-* crates stubbed; CI on Linux and macOS with cargo fmt, clippy -D warnings, tests, cargo-deny.
    • vi-core: Timestamp, ids, config loading, error type, event bus.
    • vi-media: probe; software decode of audio to 16 kHz PCM and video at N fps with keyframe seeking; sandboxed worker process; Arc<FrameBuffer>.
    • vi-index embedded backend: manifest, SQLite schema v1, blob store; Storage trait.
    • vi-cli: vi init, vi probe, vi index running only Sample + Thumbnail + PHash, vi status, vi doctor.
    • Synthetic 2-minute fixture video generated by ffmpeg in tests.

    Done when: vi index on a 1-hour MP4 produces an index directory with thumbnails and pHashes in under 5 minutes on 8 cores, and vi status reports it.

    Status: done 2026-09-11. Measured 2 min 48 s for a 1-hour 720p file on azuremc's 4 vCPUs (machine notes in vi_internal). The vector store is a stub and sandboxing is rlimits only; both are M1 work.

    M1. Coarse index and search¶

    • YtDlp, Http, ObjectStore acquirers; playlist expansion.
    • Operators: VAD, ASR (openai_compat), ShotBoundary, ImageEmbed (onnx_local SigLIP), OCR (onnx_local RapidOCR), subtitle import.
    • Lance vectors, FTS5 text, hybrid search with RRF and temporal fusion.
    • Scheduler with checkpoints, cache, budgets, progress events.
    • vi search.

    Done when: the two playlists in dataset/videolist.md index to coarse unattended, and vi search answers transcript, OCR, and visual queries with correct timestamps on the 50-question dev set's retrieval subset.

    Progress 2026-09-11: LocalFile sidecar import (.info.json, .srt, .vtt), the content-addressed media cache move from incoming/, chapter import, the subtitle_import operator, directory expansion, and the YtDlp acquirer with playlist expansion are done. vi search exists over the text index (BM25 per kind, RRF, chapter grouping, thumbnails). Remaining: Http and ObjectStore acquirers, VAD, ASR, ShotBoundary, ImageEmbed, OCR, Lance vectors and vector search in the fusion, budgets.

    Progress 2026-09-11 (GCP machine): vi-providers skeleton: capability traits (Vlm, Llm, Asr, Ocr, TextEmbedder, ImageEmbedder, Reranker) with request/response types, ProviderRegistry binding [roles] to adapters, Governor (per-provider semaphore, request and token buckets), retries with exponential backoff and jitter honouring Retry-After, CallStats → Provenance, key redaction, and the openai_compat adapter's ASR method (verbose_json with word timings, tested against a fake server). A local Whisper server runs on the GPU (scripts/asr_server.sh). Then the vad operator (Silero through ONNX Runtime, batched, SpeechRange items carry PCM) and the asr operator (concurrent requests through the asr role, word-level timings, per-request provenance, spans split on word timings). Measured on a 34-minute dataset video with config/gcp-a100.toml and the coarse_asr policy: 32 min of speech transcribed in 65 s (29× real time), whole job 81 s, bounded by video decode. ShotBoundary (HSV histogram + edge change ratio, adaptive threshold, gap-free shot segments; 12 shots on the fixture). ImageEmbed (SigLIP base through ONNX Runtime, pHash-distinct frames) and TextEmbed (bge-small) through the onnx_local adapter, with a real vector store (flat memory-mapped files, exact search) behind Storage::vector_search. Hybrid vi search (BM25 + text-vector + image-vector lists, RRF, grouping by scenes/shots/chapters/windows, --kind frame, --text-only). Ocr (RapidOCR, change-gated, collapsed across frames; 841 lines from a 47-minute lecture). Scheduler: budgets enforced, operator output cache with per-stage skip/replay/run planning, provider failures recorded per range with the job continuing. Http and ObjectStore acquirers (limits, private-address refusal, resume, prefix expansion) and the auto default policy (coarse_only when roles are bound). Remaining for the definition of done: the two-playlist run and dataset/devset.jsonl.

    M2. Fine index, agent, Python¶

    Progress 2026-09-11 (GCP machine): vi-providers adapters for openai_compat chat and embeddings, anthropic and gemini (streaming, tools, images, native video for Gemini, cost accounting, price tables, prompt registry) and vi-agent (tool-using loop, budgets, citations, sessions, RetrievalOnlyPolicy, vi ask, vi view, vi timeline) are done. The fine-pass operators scenes, chapters, vlm_describe and entities_events exist and lecture_default plans end to end when the roles are bound. The Python binding exists (bindings/python: Index.create/open/add/search/ask/aask/view/frame/timeline/status, Budget, Config, prompt overrides; smoke-tested with pytest). Python-side operators (@vi.operator, vi.Operator, Index.register_operator, inline policies) and agent policies (vi.Policy passed to ask) landed on 2026-09-12 with pytest coverage. The QA dev set (52 questions, dataset/devset_qa.jsonl) scored 96.2% with citations on 2026-09-12 (the M1 report (vi_internal/docs/reports/M1-REPORT.md); 86.5% before the full-text query fix), above the 80% target; the retrieval-only baseline is 73.1%. The fine pass over the dataset was measured on 2026-09-12 (5 h 8 min, $45.96; see the M1 report in vi_internal, which also compares the fine index against the coarse one on the dev set). Remaining: wheels verified in CI.

    • Scenes and chapters; VLM describe with frame grids and native video; entities and events; text embeddings.
    • vi-providers: gemini, anthropic, openai_compat adapters with capabilities, rate limits, cost accounting, prompt registry.
    • vi-agent: default tool-using policy, all tools in 06, budgets, streaming events, sessions.
    • vi ask.
    • Python binding with sync and async APIs, NumPy frames, operator and policy callbacks, typed stubs, wheels in CI.

    Done when: idx.ask from Python answers the 50-question dev set at or above 80% with citations, and the retrieval-only baseline number is reported next to it.

    M3. Node, server, MCP, chat app¶

    Progress 2026-09-12: vi-server (HTTP API, SSE for jobs and answers, blobs, bearer keys with a daily spend cap, MCP, /metrics, /v1/openapi.json) and vi serve are done with end-to-end tests over a real socket. The chat app (streaming answers, YouTube player seeking to citations, API proxy holding the key), the site and the MkDocs SDK docs live in the separate videoindex_app repository with Caddy and systemd templates; verified end to end on the machine over the dataset index (public DNS and ports are the operator's step). The Node binding (bindings/node, napi-rs: Index.open/create/videos/status/timeline/search/add, ask as an AsyncIterable) builds and passes its test; prebuilt binaries are produced by the CI matrix. Remaining for M3: pointing videoindex.app at the host.

    • Node binding with prebuilt binaries.
    • vi-server: HTTP API, SSE, blobs, API keys, MCP.
    • apps/chat: demo QnA app over the dataset videos with a player that seeks to citations, deployed at videoindex.app.
    • Deployment per the deployment notes in the internal vi_internal repository.

    Done when: a question typed in the browser at videoindex.app streams an answer with clickable timestamps over the AI Engineer and Berkeley playlists.

    M4. Evaluation¶

    Progress 2026-09-12: eval/ exists (loaders for LVBench, MINERVA and 1H-VideoQA, yt-dlp acquisition, vi index runner with the YouTube-key to video-id map, vi ask answer runner with stratified sampling and letter parsing, a uniform-sampling baseline through the Anthropic API, metrics with Wilson intervals, a report with a pareto plot). YouTube is reachable from the GCP host with yt-dlp + deno, so acquisition runs here; LVBench (103 videos) and MINERVA annotations (1,291 questions, 188 videos) are downloaded, LVBench videos are being fetched and indexed. Results: docs/results/lvbench-f0.25-2026-09-13.md (25% stratified LVBench sample, 340 questions over the 92 reachable videos: agent 66.2%, retrieval-only 50.3%, uniform-32-frames baseline 52.1%, Gemini 3.8 Flash agentic video 80.8% as a run-once reference) and docs/results/minerva-f0.25-2026-09-13.md (25% MINERVA sample, 310 questions: agent 51.9%, retrieval-only 37.1%, uniform-32 41.3%, Gemini 76.5%). Both pages read the same way: the index carries speech and on-screen text; the visual side (perception, counting, summarising a whole video) is where Gemini's agent over raw video leads, and the levers are a stronger frame model, a whole-video view step and denser views. Sampled runs (eval.run <config> --fraction 0.25) are the working mode while the core is iterated; 1H-VideoQA needs a Kaggle export.

    • eval/ harness, loaders for LVBench and Minerva, 1H-VideoQA if obtainable, baselines, reports.
    • Provider and policy sweeps on azuremc; pareto plots.
    • Tune sampling, grids, prompts, and policy from results; port winning policies to Rust.

    Done when: a report in docs/results/ shows accuracy, tokens, and cost per configuration on LVBench and Minerva, including uniform-sampling and retrieval-only baselines.

    M5. Hosted mode¶

    • Postgres + pgvector + object storage backend behind the Storage trait.
    • Tenants, quotas, usage metering, key management.
    • SDK site with docs at videoindex.app.
    • Optional: Qdrant backend, hardware decode on the server GPU, whisper.cpp local ASR.

    Done when: two API keys can index and query independent indexes on videoindex.app with usage recorded.

    Later¶

    Live streams, UniFFI for Swift and Kotlin, WASM query-only reader, multi-index federation, video-native retrieval models.

    Repository layout¶

    As given in 02-architecture. apps/ and eval/ depend on the SDK; nothing in crates/ depends on them.

    Licensing¶

    Proposal: Apache-2.0 for crates/, bindings/, eval/, and docs/. apps/chat and apps/site may stay proprietary if the hosted product needs it; keep them in the same repo behind a clear directory boundary or split them later.

    Open questions¶

    • Confirm the license.
    • Confirm the current Minerva download location. 1H-VideoQA is at github.com/google-deepmind/1h-videoqa (101 questions, 21 videos), resolved.
    • azuremc hardware: GPU present or not decides whether ASR and image embeddings run locally on it. vi doctor reports this; the kickoff prompt checks it first.
    • Minimum versions: Python 3.10, Node 20. Confirm.
    • Hosted tenancy model: one index per tenant, or shared indexes with row-level tenant ids.
    • Whether the chat app should stay in this repo or move once the SDK is published.
