    Decisions¶

    One dated bullet per decision made where the design documents were silent or had to change. Newest at the bottom.

    • 2026-09-11: /data is a plain directory on the root filesystem (164 G free), not a separate volume. Neither existing disk has the 500 G the deployment doc plans for; a dedicated data disk is deferred until benchmark media (M4) needs it. The ephemeral /mnt disk is never used for media or indexes.
    • 2026-09-11: The M0 "under 5 minutes for a 1-hour MP4" target is measured on this machine's 4 vCPUs, not the 8 cores the docs assume. The number is recorded either way; if it misses on 4 cores the doc target is annotated rather than the machine upgraded.
    • 2026-09-11: The M0 timing test uses a synthetic 1-hour 720p H.264 file (ffmpeg testsrc2, 30 fps, GOP 150) because no real hour-long video exists on the machine yet and YouTube is blocked. Real dataset videos re-run the measurement once transferred.
    • 2026-09-11: yt-dlp is installed as the upstream standalone binary in /usr/local/bin, not the Ubuntu package (which is a year old and breaks against YouTube). It is only for vi doctor and the YtDlp acquirer on machines where YouTube is reachable.
    • 2026-09-11: nginx already runs on this machine for other sites and port 8080 is taken by another app. The deployment doc's Caddy-on-80/443 and vi serve on 8080 will be adjusted at M3 (nginx site + a free localhost port); 11-deployment.md is updated when that work happens, not now.
    • 2026-09-11: libav is reached through ffmpeg-next 9.0, not rsmpeg. ffmpeg-next wraps contexts, frames, packets, scalers and resamplers in safe types, so vi-media holds almost no unsafe (only mmap and the pre-exec rlimit hook), and its build script detects any libav from 3.0 to 9.0 via pkg-config, which covers the distro ffmpeg 6.1 here and Homebrew's current ffmpeg on macOS CI without pinning. rsmpeg pins to one ffmpeg release and exposes a near-raw C API.
    • 2026-09-11: One decode worker process per request (probe, video decode, audio decode). Spawning costs a few milliseconds, each request is crash-isolated, and the client API stays trivial. A worker pool can be added behind the same vi_media::client functions when concurrency needs it.
    • 2026-09-11: Frames cross the worker boundary through file-backed shared memory (/dev/shm on Linux, temp dir elsewhere) divided into fixed-size slots. Slot ownership moves with protocol messages: the worker owns a slot until it announces Frame{slot}, the parent until the Arc<FrameBuffer> drops and sends SlotFree. The slot count (media.worker.max_in_flight_frames, default 16) is the per-job frame bound; pipeline channel capacities are derived from it so backpressure cannot deadlock.
    • 2026-09-11: Frames are scaled inside the worker to media.sample_max_dim (default 640 px longest side) before crossing to the parent. Nothing in the coarse pass needs more (pHash 32x32, thumbnails 320 px, SigLIP 384 px), and it cuts shared-memory traffic and swscale work roughly fourfold for 720p.
    • 2026-09-11: When the sampling rate is far below the source frame rate the decoder skips non-reference frames (AVDISCARD_NONREF). That is lossless for the frames kept and cut the 1-hour 720p decode from 259 s to 139 s on this CPU (ffmpeg CLI baseline; the worker measured 150 s). The sampled frame can land up to two frames after the target; its true PTS is stored. Per-target keyframe seeking is used only when the sampling interval is at least twice the keyframe interval. skip_loop_filter (a further ~15%) is left off to keep thumbnails clean.
    • 2026-09-11: Sandboxing in M0 is rlimits (address space, open files, no core dumps) plus PR_SET_NO_NEW_PRIVS on Linux, applied in a pre_exec hook. seccomp and macOS sandbox-exec are deferred; the process boundary and idle timeout already exist. vi doctor prints what is active.
    • 2026-09-11: The Storage trait gained methods the pipeline and CLI need beyond 04-data-model.md: get_video, find_video_by_hash, list_videos, set_index_state, put_tracks/tracks, put_frame_samples, update_frame_phash, update_frame_thumbnail, delete_frame_samples, frame_samples, put_embeddings, list_jobs, stats. The doc is updated in the same commit.
    • 2026-09-11: Operators stream their outputs through OpContext::emit instead of returning them in OpOutput, and have a finish hook for flushing buffered writes. A Vec return would hold an hour of frames in memory and defeat the bounded-channel backpressure.
    • 2026-09-11: The vector store is a stub: put_embeddings records metadata rows in SQLite, vectors are dropped, vector_search returns nothing. Lance lands in M1 behind the same trait.
    • 2026-09-11: Video rows are keyed by media content hash: re-indexing the same bytes reuses the VideoId. Parent tables are upserted (ON CONFLICT DO UPDATE), never INSERT OR REPLACE, because REPLACE deletes the row and the ON DELETE CASCADE would wipe tracks and samples.
    • 2026-09-11: A built-in m0 policy (sample, phash, thumbnail) is the default policy until M1 operators exist. Policies naming unimplemented operators (vad, asr, ...) fail with "not implemented yet" and exit code 6, distinct from typos (exit 2). After the m0 policy the video is marked coarse: the state records that the policy's coarse pass finished, not that every coarse operator in the design ran.
    • 2026-09-11: vi-testkit is an extra workspace crate (not in the 02-architecture.md layout) whose build script generates the 2-minute fixture with the ffmpeg CLI. It is a dev-dependency only, so building vi needs no ffmpeg binary. Solid-colour segments alone defeat pHash (constant luma has no DCT structure), so each segment carries a white box at a segment-specific position.
    • 2026-09-11: Lossy WebP thumbnails use the webp crate (bundled libwebp) at quality 75 because the image crate only writes lossless WebP, which would be roughly five times larger per hour of video.
    • 2026-09-11: Default server bind is 127.0.0.1:8090, not 8080, because 8080 is taken on this machine (see MACHINE-azuremc.md). 11-deployment.md is updated at M3 when the server exists.
    • 2026-09-11: Dev-profile dependencies are compiled with opt-level = 2 so libwebp and image resizing run at a usable speed in tests; workspace crates stay unoptimised for debugging.
    • 2026-09-11: M1 starts with sidecar import. LocalFile reads <stem>.info.json and <stem>[.lang].{srt,vtt}; files under <media.cache_dir>/incoming/ are moved (with sidecars) to <cache_dir>/<blake3>.<ext>, files elsewhere stay put. source_uri becomes the sidecar's webpage_url when present so a transferred download keeps its origin; the local path is in the stored probe. A duplicate in incoming/ whose hash is already cached is deleted rather than kept.
    • 2026-09-11: Subtitle cues are grouped into spans of about 15 s (new span after a gap over 2 s) before storage; single cues are too short to rank well in BM25. YouTube's rolling two-line auto-captions are collapsed to their new material. Human-authored subtitles (listed under subtitles in .info.json) get confidence 1.0, automatic captions 0.6, so ASR (when it exists) can prefer to replace only the automatic ones. Sidecar subtitle tracks use stream_index >= 1000 because they have no container stream.
    • 2026-09-11: Chapters from .info.json (else container chapters) are written as chapter Segments during acquisition by the scheduler, not by an operator: they are metadata that needs no decoding, and the fine-pass chapters operator can later replace them with topic segmentation when neither source has them.
    • 2026-09-11: The default policy is now coarse_local (subtitle_import, sample, phash, thumbnail): everything that runs without a model provider. m0 remains for the timing benchmark.
    • 2026-09-11: YtDlp downloads into <cache_dir>/incoming/ with the same fixed argument set as scripts/download_videos.sh (720p MP4, .info.json, subtitles and auto-captions converted to SRT, embedded chapters, download archive) and then reuses LocalFile, so both paths produce identical index contents. The URL is passed after -- so user input can never be read as a flag. Playlists expand via --flat-playlist.
    • 2026-09-11: vi search (M1, text only so far) fuses per-kind BM25 lists with reciprocal rank fusion (k = 60), then groups evidence by the chapter segment containing it, or by 60 s windows when a video has no chapters. A group scores best + 0.3 × sum(others), so a chapter where transcript and on-screen text agree outranks a single lucky keyword. Scene segments replace chapters as the grouping unit once shot and scene detection exist. Query words are ANDed with a prefix match on the last word; quoting is escaped so user text cannot inject FTS5 syntax.
    • 2026-09-11 (GCP): Development moved to a GCP a2-ultragpu-1g (12 vCPUs, 167 GiB, one A100 80 GB, Ubuntu 26.04, ffmpeg 8.0). docs/MACHINE.md describes it; the azuremc file keeps its name. The kickoff prompt assumed a2-highgpu with 40 GB; with 80 GB a 32B VLM fits in fp16 on one GPU, so no quantisation or tensor parallelism is planned.
    • 2026-09-11 (GCP): The blank 375 GB local SSD (/dev/nvme0n1) was left unformatted: the kickoff session's permission policy refused the mkfs, and nothing needs it yet (/dev/shm is 84 GB, the OS disk has 715 GB free for target/). Format and mount it at /mnt/localssd by hand if build times or temp files ever matter.
    • 2026-09-11 (GCP): No Docker on this machine yet. The Whisper server runs as a plain user process: faster-whisper in a uv-managed Python 3.12 venv (/data/videoindex/asr/.venv; the system Python 3.14 has no ML wheels) with the CUDA 12 runtime supplied by the nvidia-cublas-cu12 and nvidia-cudnn-cu12 pip wheels, so no system CUDA install was needed. scripts/asr-server/server.py is a small FastAPI app implementing the OpenAI /v1/audio/transcriptions shape (verbose_json with word timestamps) over BatchedInferencePipeline; scripts/asr_server.sh start|stop|status manages it on 127.0.0.1:9000. A container and a systemd unit can replace this later without touching the openai_compat adapter.
    • 2026-09-11 (GCP): ONNX Runtime models run on the CPU until a CUDA toolkit (cudart, cuBLAS, cuDNN 9) is installed system-wide, which the kickoff says to ask about first. vi doctor reports whether those libraries are present. Model files live under /data/videoindex/models/<model>/; the operators take their paths from config and refuse to start with a download hint when a file is missing. SigLIP is Xenova/siglip-base-patch16-224 (768-dim) because no ONNX export of so400m-patch14-384 exists on the Hub; swapping models is a config change.
    • 2026-09-11 (GCP): vi-providers holds the capability traits, the role registry, the per-provider Governor (semaphore + token buckets), retries and cost accounting, and the HTTP adapters. Local ONNX adapters implement the same traits from vi-perceive (which owns the ONNX Runtime sessions) and plug into the registry through register_factory("onnx_local", ...), so vi-providers never depends on ONNX Runtime and vi-perceive stays the only crate that does. The pipeline registers the factory at start-up.
    • 2026-09-11 (GCP): Provider tables gained typed fields (concurrency, requests_per_minute, tokens_per_minute, timeout_secs, max_retries, pricing, model_dir) next to the free-form extra map, and vi_core::Error::Provider (exit code 8) distinguishes a failed or unbound provider from an unsupported feature. No providers or roles are configured by default; coarse_local stays the default policy and provider-backed operators fail at plan time with the role that is missing.
    • 2026-09-11 (GCP): Silero VAD runs through the ort crate (ONNX Runtime 1.23 prebuilt binaries downloaded at build time, rustls for the download, no tracing feature so ONNX Runtime's own INFO chatter stays out of the logs). Model files live under models.dir (/data/videoindex/models on servers, ~/.cache/videoindex/models otherwise), one subdirectory per model; a missing file fails at operator start with the download hint. The whole audio track is decoded to memory (16 kHz mono i16, 115 MB per hour) and scored in one pass with 32 parts of the recording batched through the model in lockstep, because one ONNX Runtime call per 32 ms window cost more than the arithmetic: 24 s → 14 s for a 34-minute track including the decode.
    • 2026-09-11 (GCP): VAD segments are long on purpose (max_segment_secs 120, min_silence_ms 1000): the batched Whisper server splits each request into 30 s pieces at pauses and fills its GPU batch, so 70 requests of ~27 s transcribe 32 minutes of speech in 65 s (29× real time, 4 concurrent requests), against 17× with 146 requests of ~13 s. Segments still start and end at detected silences, so no word is cut. The ASR operator carries the PCM inside the SpeechRange item (bounded channels keep at most ~8 items, 30 MB, in flight) instead of re-decoding per range.
    • 2026-09-11 (GCP): Whisper's batched decoder returns one segment per 30 s piece, so the ASR operator splits segments longer than models.asr.span_secs (15 s) on word timings, cutting after sentence-final punctuation in the second half of a piece or else at the longest pause, then groups short segments as subtitle_import does. Word timings are stored as {"w","s","e","p"} with absolute seconds. Each ASR request writes its own Provenance row (provider, model, media seconds, latency, attempts) so cost roll-ups work per request.
    • 2026-09-11 (GCP): subtitle_import skips a sidecar whose cue text is identical to one already imported (yt-dlp writes YouTube auto-captions twice, as en and en-orig), and the rolling-caption collapse now also recognises a cue that repeats the second line of the previous two-line cue, which is how yt-dlp's current SRT conversion rolls. Before this each auto-caption sentence appeared four times in the index.
    • 2026-09-11 (GCP): Provider-backed operators declare required_roles(); the scheduler checks the bindings at plan time and fails with exit code 8 naming the role, so an unconfigured provider is reported before any decoding. config/gcp-a100.toml is the config for this machine (Whisper on 127.0.0.1:9000, ONNX models under /data/videoindex/models, a coarse_asr policy); pass it with --config or VI_CONFIG.
    • 2026-09-11 (GCP): shot_boundary compares consecutive sampled frames (1 fps), so its shots are runs of visually continuous samples and a cut is placed at the first sample of the new shot; at that rate a shot is never shorter than the sampling interval, which is what slide-based lectures need. The distance is 0.5 × (1 − HSV histogram intersection, 8×4×4 bins) + 0.5 × edge change ratio on a 96-pixel-wide grey image with one pixel of dilation tolerance; a cut needs the distance above 0.25 and either above 0.7 or above mean + 3σ and 2.5× the mean of the last 20 within-shot distances. The segments start at 0 and end at the video duration so the shot level has no gaps, and each carries its first sample as keyframe_sample_id. The 2-minute fixture (a hard cut every 10 s with a burned-in timer) yields exactly 12 shots, asserted in the pipeline tests.
    • 2026-09-11 (GCP): Shot detection does not try to catch text-only slide changes. On the AI Engineer VC talk (white slides, small speaker inset, sponsor logos swapping every 10 s) a title change moves 2 to 9% of the pixels of the small grey image and about 10% of the edges, the same as a logo swap, so no threshold separates them; the 34-minute talk is six shots. Slide changes are detected from OCR text instead: the ocr operator runs on frames whose pixel-change measure (FrameSignature::pixel_change) fires, not only on pHash-distinct frames (a pHash of a mostly white slide ignores its text), and consecutive identical text collapses. cargo run -p vi-perceive --example shot_debug -- <file> [t0] [t1] prints the per-sample metrics for tuning.
    • 2026-09-11 (GCP): The vector store is a flat, append-only, memory-mapped file pair per model (vectors/<model>.vec with normalised f32 rows, <model>.meta with embedding id, video id, target kind and an alive flag per row) searched exactly by brute force on rayon, not Lance. lance 11 pulls 689 crates (Arrow, DataFusion, an object-store stack) into a workspace of about 250 for a feature that at M1 to M4 scale (hundreds of thousands of vectors) runs in single-digit milliseconds with exact results, which the eval harness prefers over approximate ones. Deletes flip the alive flag, compact rewrites the files and updates the row column added to embeddings in schema v2, and put_embeddings replaces an earlier vector for the same (target, model). Lance or usearch remain a drop-in behind Storage when approximate search is needed. 04-data-model.md is updated.
    • 2026-09-11 (GCP): image_embed consumes Hashed items, which now carry the frame, and embeds only frames farther than PHASH_DEDUP_DISTANCE from the previously embedded one (47 of 2,057 frames on the VC talk, about a third on slide-heavy lectures). Pixels are copied out to an owned buffer before batching so decoder slots are released at once; SigLIP base on 6 CPU cores embeds a batch of 16 in about 4 s. text_embed embeds transcript and OCR spans with bge-small (32 per batch, 342 spans in 11.6 s of CPU); its OcrSpan input is optional so it runs in policies without ocr. Operators declare optional_inputs() for exactly this.
    • 2026-09-11 (GCP): vi search is hybrid: per-kind BM25 lists, a text-vector list (bge-small, query prefixed with bge's retrieval instruction through TextEmbedder::embed_query) over transcript, OCR and description rows, and an image-vector list (SigLIP text tower) over frame embeddings, fused with RRF (k = 60). Grouping units are scenes when they exist, else shots cut into pieces of about 60 s (so a 29-minute static shot does not swallow a whole talk), else chapters, else 60 s windows; the chapter title is still reported when the unit falls inside one. Each piece of evidence lists the lists that ranked it (bm25:transcript, text_vec, image_vec) so relevance can be debugged. Query embedders load lazily and the SigLIP towers load one at a time, so a text query pays for bge and the SigLIP text tower only (about 1.5 s of model loading in the one-shot CLI; the server keeps them resident).
    • 2026-09-11 (GCP): sample writes each FrameSample row before emitting the frame. Batching rows raced image_embed, whose embeddings reference the sample id: the vector's video could not be resolved and search then grouped it under a nil video. A per-frame insert is a few thousand statements per hour of video.
    • 2026-09-11 (GCP): OCR is RapidOCR in-process: the PP-OCRv4 detector (DB, 960 px longest side, threshold 0.3, box score 0.5, unclip 1.6, axis-aligned boxes from connected components) and the English PP-OCRv3 recogniser (CTC, height 48, batches of 8 sorted by aspect ratio, en_dict.txt + blank + space = 97 classes). The ocr operator reads a frame when its pHash moved past the dedup distance, or its pixel-change measure against the last frame read is at least models.ocr.min_pixel_change (2%), or max_gap_secs (30 s) passed; lines already present in the previous read are not stored again. On a 47-minute slide lecture that read 247 of 2,815 frames and stored 841 lines, inside the decode's shadow. Reading order is rows by centre then left to right; boxes are stored normalised.
    • 2026-09-11 (GCP): The operator output cache is a marker file per completed stage under <index>/cache/operators/, keyed by content hash, operator id and version, and the operator's cache_params() (provider, model, thresholds, sampling rate). The outputs themselves are the rows in the index (videos are keyed by content hash, so identical content already shares them). At plan time each stage is run, replayed or skipped: skipped when cached and no running consumer needs its items; replayed (Operator::replay, re-emitting stored spans or segments without recomputing: subtitle_import, asr, ocr, shot_boundary) when cached but a consumer runs; run otherwise, and always run when one of its producers runs, because a re-run producer replaces the rows the stage's outputs hang off. This replaces M0's all-or-nothing resume: adding ocr to a policy after a coarse_asr run re-decodes (sampling cannot replay) but leaves ASR and VAD untouched, and text_embed gets its transcript spans replayed. --force ignores markers; a stage that skipped or failed inputs leaves no marker so the next run completes it.
    • 2026-09-11 (GCP): Budgets: Budget::for_policy turns max_cost_usd_per_hour and max_wallclock_per_hour (now parsed: 20m, 1h30m, 90s; 0 means unlimited) into a per-job ceiling using the video's duration (at least a minute's worth). Provider-backed operators call allow_provider_call() before each call and record spend from CallStats; once a limit is hit no further calls are issued, the inputs are counted as skipped, the stage completes, and the report says which limit stopped it. Provider errors after the adapter's retries are recorded per input range (first 50 kept with times and messages) and the stage continues; a stage whose every input failed is marked failed and the video ends failed.
    • 2026-09-11 (GCP): Http and ObjectStore acquirers download into <cache_dir>/incoming/<8-char URL hash>-<file name> and then reuse LocalFile, so all four acquirers produce identical index contents and sidecars next to a remote object (.info.json, .srt) are picked up. Http claims only URLs whose path ends in a media extension (video-site URLs stay with YtDlp), disables automatic redirects and resolves every hop's host itself, refusing private, loopback, link-local, CGNAT and metadata addresses unless media.download.allow_private_addresses is set; it resumes with Range, enforces max_bytes from Content-Length/Content-Range and while streaming, and rejects text/html bodies. ObjectStore uses the object_store crate with credentials from the environment; r2:// is S3 with media.download.r2_endpoint or R2_ENDPOINT; a URL ending in / expands to the media objects under the prefix. Tests run against a local HTTP stand-in and object_store's local filesystem store.
    • 2026-09-11 (GCP): default_policy defaults to auto: coarse_only (every coarse operator: subtitles, VAD, ASR, sampling, shots, pHash, thumbnails, SigLIP, OCR, bge) when the asr, ocr, image_embed and text_embed roles are all bound, else coarse_local. lecture_default keeps the fine pass (scenes, chapters, vlm_describe, entities_events) and fails at plan time until M2 implements them; text_embed moved into the coarse pass because hybrid search needs span vectors before any VLM runs.
    • 2026-09-11 (GCP): No sort comparator may use a tolerance or partial_cmp(..).unwrap_or(Equal): Rust's sort panics on comparators that are not total orders, and the OCR reading-order sort (rows matched within half a box height) did exactly that on the first long workshop, killing the rayon task and failing every OCR read of that video. Reading order now sorts by centre y, groups rows greedily, and sorts each row by x; every float sort uses total_cmp.
    • 2026-09-11 (GCP): dataset/devset.jsonl holds the retrieval dev set: 72 questions over all 30 dataset videos (65 transcript, 3 OCR, 4 visual). Transcript and OCR questions carry an anchor phrase that scripts/devset_eval.py resolves to a time from the video's captions (or the index's OCR spans), so ground truth follows the media rather than hand-typed seconds; visual questions carry t0/t1 from contact sheets. A hit counts when the result's video matches and its range, widened by 30 s, overlaps the anchor's range (cue time −5 s to +30 s). The questions are paraphrases, not caption text, so BM25 alone misses many of them and the vector lists have to earn their place.
    • 2026-09-11 (GCP, M2): Chat adapters share one SSE parser (vi_providers::sse, also accepts JSON lines) and stream GenerateEvents from futures::stream::unfold state machines, so tool-call fragments are assembled per adapter (OpenAI by index, Anthropic by content block, Gemini whole per part) and every stream ends with Usage then Done { finish_reason, stats } with finish_reason normalised to stop, length or tool_use. Images go in as base64 JPEG (quality 85) from raw RGB; only Gemini takes video inline (under 19 MB; file upload is deferred). ContentPart::ToolCall/ToolResult carry the tool name because Gemini keys function responses by name, not id. Default prices per model family live in vi_providers::pricing and are overridable per provider; they are estimates to check against vendor lists. Anthropic rejects temperature on Claude 5 models, so it is sent only when non-zero; a live call to claude-sonnet-5 with one tool costs about $0.003 and 2 s.
    • 2026-09-11 (GCP, M2): vi-agent runs the loop from 06-query-and-agents.md around the agent_llm/agent_vlm roles: a system prompt (versioned in vi-providers/prompts/agent_system.md, hash recorded) plus a compact list of the index's videos (id, duration, title) when there are at most 40, then a tool-using generation loop. Tools: search, list_videos, timeline, get_transcript, get_ocr, get_descriptions, view, and describe when a vlm_describe role is bound. Tool results are JSON text; a view grid follows as an image in a user turn because OpenAI-shaped APIs cannot carry images in tool messages. Citations are inline markers [[cite:VIDEO_ID:T0-T1]] that a streaming scanner removes from the token stream and emits as Citation events typed by the evidence the loop has seen (transcript, ocr, frame, description, else range); markers naming unknown videos are dropped. Budgets (max_tokens, max_cost_usd, max_wallclock_secs, max_tool_calls) are checked before each provider call; when one is hit the model is asked to answer from what it has and Done { partial: true, reason } says which limit. Sessions keep the last 20 question/answer pairs in the sessions table with a 24 h TTL. Policy decides tools for baselines (RetrievalOnlyPolicy: one search, then answer); the LLM still writes the answer. First live run on the VC talk: 3 tool calls, correct timestamps, $0.065, 14.6 s with claude-sonnet-5.
    • 2026-09-11 (GCP, M2): Frame grids are composed in vi-perceive::grid with a built-in 5×7 bitmap font for the HH:MM:SS labels (no font files or text-rendering crates), nearest-neighbour tiles, view clamps to 120 s and 16 frames (lowering fps), and grids are stored as PNG blobs so a citation of a view can be rendered later. The first run rendered 9 frames of the VC talk in 1.8 s including decode.
    • 2026-09-11 (GCP, M2): The fine pass. scenes groups shots with a boundary strength of 1 − cosine(keyframe SigLIP embeddings) halved when a transcript span crosses the boundary, merging across weak boundaries (< 0.5) and any scene under 20 s while staying under 180 s; shots get parent_id. chapters keeps imported chapters when the source had them; otherwise it embeds each scene's transcript with the text_embed role, computes TextTiling-style depth scores over the scene sequence, adds a bonus where the first title-like OCR line changes, and picks boundaries for about one chapter per 10 minutes with a 3-minute minimum, titling each from its first title-like OCR line. vlm_describe sends a 3×3 grid of a scene (fps chosen to fit nine frames) plus the scene transcript as data to the vlm_describe role with the versioned prompt, asks for JSON when the provider supports schemas, stores a Structured Description (flattened text for FTS and embeddings, JSON kept) and writes the summary onto the scene; the grid is kept as a blob. entities_events sends 5-minute windows of descriptions and transcript to the extract_llm role and stores entities (canonicalised by lower-cased name) with mentions and events; a re-run replaces a video's extractions. All four honour the job budget and record per-range failures. A job whose policy has fine operators ends in state fine.
    • 2026-09-11 (GCP, M2): The Python binding (bindings/python, PyO3 0.29 + maturin, abi3 for Python 3.10+) owns one tokio runtime and releases the GIL (Python::detach) around every core call. Index.add returns a Job whose progress() iterates the event bus and wait() returns the reports; search, timeline, videos, status return plain dicts (JSON through serde, {num, den} timestamps flattened to seconds); ask returns an AskStream usable with for or async for (pyo3-async-runtimes) or drained with collect(). frame returns a NumPy HxWx3 uint8 array as a copy of the decoded buffer; the zero-copy buffer-protocol view over Arc<FrameBuffer> in 03-rust-boundary.md is deferred until a caller needs it (a 640 px frame copies in microseconds). Custom operators and policies from Python are not wired yet. The decode worker cannot be the Python process, so media.worker.path must point at a vi or vi-media-worker binary; the wheel will bundle the worker later. Tests: pytest bindings/python/tests after maturin develop.
    • 2026-09-11 (GCP, M2): First full-pass run on the VC talk found two defects: a 29-minute static shot became one scene (scenes now cut shots longer than 180 s into pieces of about 120 s, snapped to transcript span starts), and the extraction model wrapped its JSON in prose or ran out of tokens (the first {...} object is now extracted and the budget is 4,000 tokens). Stages that store without emitting (embeddings, extraction) are no longer judged failed when one batch fails: the all-failed rule counts stored rows too.
    • 2026-09-11 (GCP): The decode worker is spawned from /proc/self/exe on Linux, not from current_exe()'s path. Rebuilding vi while a long index job ran replaced the binary on disk; every later worker spawn failed with "failed to spawn .../vi" and 25 of 30 videos errored in seconds. /proc/self/exe stays valid for the life of the process.     • 2026-09-12: Python operators and policies. Custom operators plug in through Scheduler::register_operator(name, factory); a factory builds a fresh operator per job so per-job state never crosses jobs. A custom operator with a built-in name replaces the built-in one (that is how an experiment swaps a stage). Items cross the boundary as JSON dicts plus NumPy arrays for pixels and audio; rows come back as JSON and vi_pipeline::callback::store_rows turns them into stored rows (ids, provenance, timestamps at a 1 MHz timebase) before emitting them, so bindings never touch storage themselves. A Python operator's outputs are cached under its id, version and params like any stage, and its run executes on a tokio blocking thread holding the GIL only for the call. Operator ids are &'static str in the trait; a registered Python id is leaked once, which is fine for a handful of registrations per process. Inline policies (add(..., policy={...})) default unset operator lists to empty rather than lecture_default, so a dict listing only coarse does not silently pull in the VLM stages. A Python policy returns {"tool", "args"} or None; the LLM still writes the final answer.
    • 2026-09-12: Full-text queries OR their terms. fts_query used to emit every word as a required term (FTS5's implicit AND), which is right for keyword lookups and wrong for the questions people type: on the 72-question dev set the BM25 lists were empty for almost every miss and the fusion ran on the vector lists alone. Terms are now OR-ed after dropping English stopwords (a query made only of stopwords keeps them), the last term still prefix-matches, and BM25 ranks rows matching more terms higher. The eval's caption anchors now match across up to three consecutive cues, since captions break sentences mid-phrase; eight questions were unscorable before.
